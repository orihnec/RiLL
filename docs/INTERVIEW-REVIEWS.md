# 面经记录（第一阶段）

## 使用方式

在「求职中心 → 面经」新建记录，也可以右键「准备投递 / 已投递」中的岗位，选择「记录面经」或「查看面经」。Cmd/Ctrl+K 可搜索「面经」。

公司、岗位和面试日期都可稍后补充。关联投递时会带入公司、岗位快照；删除投递或撤销飞书导入不会删除面经。复盘状态与投递进度独立。

- 场次：标题、关联投递、公司、岗位、轮次、可空日期、面试形式、原始速记、整体复盘。
- 逐题复盘：题目原话、追问、当时的回答、复盘后的参考答案、我的复盘、知识点标签、掌握程度。同一道题在不同场面试中的回答分别保存。
- 浏览：按面试 / 按问题；全文关键词检索，以及公司、复盘状态、标签、掌握程度组合筛选。
- 编辑：支持 Markdown、代码块和预览。导出当前面经为 Markdown，包含当前编辑内容及未移除的问题。
- 回收：场次和问题都使用软删除；在回收站恢复面经，或在场次底部恢复已移除的问题。

## 保存与恢复

编辑后约 500ms 自动写入 SQLite；每次输入先同步保留本机恢复草稿。「立即保存」会等待这场面试及各题的保存队列完成。

保存失败会持续显示错误并保留草稿，继续输入不会隐藏错误或自动覆盖。可重试保存，或先导出当前内容。意外关闭后，重新进入面经页可从顶部提示恢复草稿。

每个场次和题目都有独立 revision，写入使用单条 `UPDATE … WHERE revision=… RETURNING`。另一窗口已修改的版本不能被旧窗口覆盖；冲突时可先导出，再二次确认重新载入数据库版本。不同窗口的恢复草稿分别保存，恢复失败不会移除来源草稿。

本机草稿属于当前设备的 WebView 存储，数据库属于应用数据目录；Markdown 导出可用于主动备份。第一阶段提供人工记录与复盘，AI 整理和定期复习安排留待后续阶段。

## 数据与开发验证

独立模块 `src/modules/interviews/`，追加迁移 `interviews:0`，不改历史迁移。`interview_sessions` 保存场次及投递快照，`interview_questions` 保存逐题内容。投递关联不使用级联删除。

运行 `npm run test:interviews` 验证 SQLite 迁移、持久化、软删除、版本冲突、响应丢失重试、自动保存队列、恢复草稿及 Markdown 导出；运行 `npm run test:feishu` 回归既有导入逻辑。`npm run build` 包含 TypeScript 检查与生产前端构建。
