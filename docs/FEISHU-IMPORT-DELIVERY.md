# 飞书投递导入

从“求职中心 → 从飞书导入”读取表格，核对字段和逐行结果后，将个人投递或明确待投记录写入 RiLL。设计背景见 [实施方案](FEISHU-JOB-IMPORT-PLAN.md)，连接验证范围见 [验证说明](FEISHU-P0-VALIDATION.md)。

## 配置与使用

1. 在飞书开放平台创建自己管理的应用，在“凭证与基础信息”取得 App ID / App Secret。启用用户身份权限 `sheets:spreadsheet:readonly`、`bitable:app:readonly`、`offline_access`，发布应用版本并按租户要求完成审批。
2. 将 OAuth 重定向地址设为 `http://127.0.0.1:43829/feishu/callback`。在 RiLL 本机连接界面填写凭证，完成系统浏览器中的用户授权。授权用户必须能访问目标文档。
3. 粘贴飞书链接，依次选择“检查链接”、数据表 / 视图、“读取字段与记录”。支持普通 Sheets、独立 Base 和 Sheets 内嵌 Base，通过元数据确定读取器。
4. 核对公司、岗位、个人状态、投递日期和申请链接的映射。支持多列合成、多行表头、手动起始行、真实合并区域及用户确认的公司分组继承。
5. 源表没有岗位列时，在“缺少岗位时批量填写”输入实际岗位，或逐行补录。公司和岗位必填，缺失时该行不能勾选。“流程中”等状态需要明确映射或逐行核对。
6. 生成预览并检查新增、待投、更新与关联记录。默认只选无歧义的新增记录；招聘信息、覆盖更新、身份不确定和缺必填项的记录保持未选。
7. 核对数量后点击“导入选中项”。完成后可查看投递 / 待投、来源详情、批次结果及撤销预览。

“读取”和“生成预览”不会写入正式投递。AI 辅助需要用户明确勾选并发起请求，才将最多 40 条待核对记录、50,000 字符发送给当前配置的模型，不发送 OAuth 配置或令牌。手动导入不依赖 AI。

## 数据处理

- Base 使用稳定的 `record_id`，视图不参与同源身份。Sheets 可选唯一编号；没有编号的新记录必须确认业务身份，行号和全行哈希不作稳定 ID。
- 同源重复跳过，源变化按字段三方比较，保护本地编辑和空值。跨来源或手动记录命中时，由用户选择关联或独立申请。本地删除不会自动恢复，源表缺行不会删除本地记录。
- 缺年、歧义和未来日期进入核对；未知日期为 `null`，保留原始值及精度。招聘开放状态不会成为个人通过 / 失败，笔试和未来安排不会自动提升为面试完成。
- 冻结预览、正式记录、来源绑定、审计和结果使用同一 SQLite，复用 SQL 插件连接池，在同一连接中执行 `BEGIN IMMEDIATE`。事务内重读状态配置、完整快照 / revision 及绑定；失败全回滚。
- 同批双击、并发确认、响应丢失后的重试返回同一结果。撤销先预览，只处理提交后未被编辑、删除或后续来源触及的记录；旧记录恢复前值并递增 revision。
- 历史可恢复未完成预览。逐批清理快照会让相应恢复 / 撤销失效，正式投递和去重绑定保留。
- 导入后立即刷新并通知其他窗口。未知日期显示“—”、双向排序置底、不计近期投递；待投转已投时写实际日期。支持手动补录 / 清空日期，以及在待投列表编辑来源详情。

## 升级与凭据

不修改历史 `jobs/schema.sql` 和 `jobs:0`，追加 `jobs:1`～`jobs:4`：日期已知标记、revision、extras 三个独立 ALTER，以及五张导入表。ALTER 分别检查 PRAGMA，可从中断恢复。

首次 ALTER 前在应用数据目录通过 `VACUUM INTO` 制作一致备份，多窗口共享备份锁。数据库和 keyring 的路径 / 标识兼容旧版本。未知日期底层用 `applied_at=0`、`applied_at_known=0` 表示，UI 和 service 接收 `null`。

凭据仅保存在系统 keyring，Windows 长令牌分段保存，完整写入新代后切换索引。跨窗口 / 实例通过系统文件锁串行读取、刷新和断开。源码及测试不包含真实凭据或私人表格导出。

## 验证与构建

在具备项目所需 Node、Rust 和平台编译工具的环境运行：

```sh
npm ci
npm run test:feishu
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --release --locked --lib jobs_
npm run tauri -- build
```

已有 39 项前端规则 / 连接测试、13 项原生回调 / 系统锁 / SQLite 事务测试，覆盖分页、限流、权限错误、取消、字段类型、日期、身份、冲突、回滚、并发、重试、撤销保护、快照清理和迁移恢复。

Windows 自建应用 OAuth、长凭据存储、真实 Sheets 内嵌 Base 读取和旧数据库升级已在本机验证。普通 Sheets / 独立 Base 使用模拟接口测试，真实文档联调和 macOS 真机验收仍待补充。界面检查使用虚构数据，真实业务记录由用户核对后确认导入。

## 范围与限制

当前使用用户自建应用授权，不分发公共 App Secret。Sheets 的富文本 / 公式若只返回显示标题，会提示缺少实际链接并保留原文，不猜测网址。Sheets 有 10,000 行、256 列、500,000 单元格上限；Base 同样限制行数与字节数，超限明确失败。

读取与分析可取消，提交阶段等待原子事务结果，成功后按保护规则撤销。复杂多阶段记录保守进入核对；不自动拆分单元格内的多个申请。当前没有定时同步、回写飞书或自动清理历史快照。
